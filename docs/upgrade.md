# 升级、备份与恢复

## 配置导出和完整备份

面板的“配置备份”用于迁移运行配置，继续兼容既有的加密格式和版本 1/2 配置文件。范围包括服务器及其 API Key、OpenList Token、服务器覆盖策略、客户端规则、通知配置、面板用户策略及权限模板、日志配置。

配置导出不包括管理员账户、角色和授权、管理员 API Token、登录会话、TOTP/恢复码、告警规则及投递历史、独立加密密钥、审计和播放统计。Emby 自身的用户、密码、权限和媒体库也不在面板配置备份中，需使用 Emby 自身的备份。

要保留管理员、告警及历史数据，应在停止全部面板实例后备份完整数据目录。不能在 SQLite 仍有写入时只复制 `embypanel.db`；运行中的数据可能仍在 WAL 中。

以仓库提供的 Compose 部署为例，从项目根目录执行：

```sh
docker compose stop embypanel
umask 077
mkdir -p "./backups"
backup_path="./backups/embypanel-$(date +%Y%m%d-%H%M%S)"
cp -a "./data" "$backup_path"
```

在私密的部署备份中保留 Compose 配置和外部 `EMBYPANEL_ADMIN_SECURITY_KEY`，不要将其写入 Git 或分享给他人。若已启用 2FA，恢复时必须使用原来的该环境密钥。告警使用数据目录中的 `embypanel.db.key`；备份和恢复应一并包含该文件及数据库。复制时保留文件权限，Unix 下告警密钥要求 `0600`。

采用自定义数据挂载时，备份实际挂载的完整目录。先确认备份存在且可读取，再启动原服务或更新镜像。本文的备份命令不会更新镜像或切换版本。

## 从旧版升级

当前迁移兼容 v0.2.7 的数据库：增加表和字段，保留既有账户、密码、会话及运行配置；原管理员首次迁移获得 `super_admin`。新增服务器覆盖字段默认继承全局值。

播放控制使用 `sessions.control`，与 `monitoring.read` 分离。内置 operator 获得控制能力，viewer 只读；既有只读 API Token 不会自动扩展写权限。自定义角色和 Token 需按需要显式授权。

升级前完成上述停服备份，使用确定的镜像 tag，并同时更新前后端。首次启动会进行幂等数据库迁移；启动后检查 `/healthz`、管理员登录、服务器监听以及一个授权范围内的读取和管理操作。

## 恢复与回退

恢复时先停止全部面板实例。保留当前数据目录的副本，将选择的完整备份复制到一个新的目录，配置数据挂载指向该目录，保留原有文件权限和外部密钥。先使用与备份匹配的版本启动并验证；不要把完整目录覆盖到仍运行的数据库上。

验证内容包括：

- 管理员能登录，角色和服务器授权与备份一致。
- 2FA、恢复码和告警加密配置可用。
- 服务器配置、用户模板、历史与审计仍存在。
- viewer 的读取不会触发管理操作；只读 Token 无播放控制权限。

回退到 v0.2.7 时，应使用升级前的备份及对应版本。旧程序不理解新权限、2FA 和 `revoked_at`，直接沿用升级后的数据库可能使撤销状态失效。恢复旧快照也会恢复快照中的凭据状态，恢复后应审查并撤销不再有效的账户和凭据。

## 数据保留

任务失败历史和告警投递历史采用 90 天、维护后全局最多 20,000 条的保留策略。维护由初始化、生产写入或后台定时路径按小时节流触发，维护间隔内条数可暂时超过上限；同一任务执行的重复观察会合并。保留的数据库快照不会被应用维护删除。

配置导出不保存这些历史记录。要长期保存历史，应定期保留完整数据备份。

## 验证边界

源码回归使用临时数据库模拟旧库迁移及完整目录冷备恢复，检查配置、管理员权限、会话撤销状态、TOTP 密文/恢复码和告警密钥的往返。自动化验证不读取或覆盖真实部署数据，也不代替不同 Emby/OpenList 版本的外部集成验收。
