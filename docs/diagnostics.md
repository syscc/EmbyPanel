# 链路诊断

链路诊断回答：哪个媒体请求、来自哪个客户端、为何选择这条处理路径、最终返回什么，以及时间花在哪里。它与播放日志、请求日志、拦截日志和系统日志保持独立职责，通过同一请求关联 ID 查找相关记录。

## 结果含义

- **已返回重定向**：面板返回了 HTTP 302，不代表播放器已经成功访问目标或开始播放。纯直链传输发生在播放器与目标服务器之间，面板不能据此判断后续播放结果。
- **已回源代理**：请求进入 Emby 回源路径；HTTP 状态只表示面板取得并转交的响应头，不是完整媒体传输的最终结果。
- **失败**：有实际操作失败，记录节点、错误类别及可获取的上游 HTTP 状态。
- **已取消**：请求任务在链路处理阶段被取消。不能仅据此推断是用户、客户端、代理或服务端主动取消。
- **已拦截**：本次请求被当前面板策略限制，记录实际原因，不推测客户端意图。

名称、设备、上游状态等未采集时显示占位，不能将媒体 ID 当作媒体名称，也不能仅通过客户端 UA 推测可靠的设备身份。Emby 的 PlaybackInfo 生成流地址会将请求中明确的 `Client`、`Device`/`DeviceName`、`DeviceId`、`UserId` 上下文延续到后续视频流请求，兼容对应的 `X-Emby-*` 查询参数和请求头，以及 `Authorization`、`X-Emby-Authorization`、`X-MediaBrowser-Authorization` 中的 `MediaBrowser`/`Emby` 属性。补充到流地址的请求头字段仅限这些非凭据上下文，不能从授权头复制 Token 或 API Key；原查询中的播放鉴权参数保持原有传递行为。媒体标签复用原有查询，不为缓存命中的请求增加额外媒体探测。修复只影响新生成的流地址和诊断记录，历史记录无法追补；客户端始终未提供的字段仍显示占位。

## 时间与缓存

- 起止时间是 Unix 毫秒时间戳，页面按浏览器本地时区显示，并保留毫秒精度。耗时使用单调时钟，系统时钟调整不会让活动中的诊断耗时倒退。
- 总耗时覆盖本次诊断处理，不代表媒体总传输时间或播放器首帧时间。
- 最慢步骤依据实际采集计算；未归入步骤的耗时按真实操作区间的并集计算，不能通过简单累加重叠步骤得到。
- 缓存节点可能合并查询和写入：起止时间显示这些操作的时间范围，耗时只累计缓存操作本身；不能将中间其他操作的等待算作缓存忙碌。
- 缓存状态区分命中、未命中、未启用及未检查。未命中不证明已经过期。剩余有效期只使用真实条目的有效期，不将配置 TTL 当作每次命中时剩余 TTL。
- 内部跳转解析只记录原请求已经发生的解析，不为诊断增加探测。请求至收到响应头耗时包含该请求实际经历的准备与网络过程，不能冒充独立网络分段。
- **名称解析调用耗时／次数**：统计真实完成的系统名称解析调用，包含线程池排队、系统 resolver、hosts 与缓存等开销，不能解释为单次 DNS 报文的往返耗时。静态地址覆盖、直接使用 IP 或连接池命中时可能没有解析事件。
- **连接建立尝试合计耗时／次数**：统计已完成的现有连接器调用，可能包含名称解析、多个地址的连接竞速、代理 CONNECT 和适用的 TLS。连接尝试可能未被当前响应使用；它不是纯 TCP／TLS 耗时，也不包含后续 HTTP 协议握手的全部时间。
- 两项数值是已完成事件的汇总，可能重叠，多个并行尝试的和也可能大于墙钟耗时。它们不额外计入诊断总耗时或未归属耗时。
- 用户解析、播放策略及其通知步骤会汇总其中原有 HTTP 发送的网络观测；即使随后命中直链缓存，或媒体查询复用前一步建立的连接，也不会丢弃前一步的观测。可选子查询的错误或状态码不会覆盖整体处理结果。
- 观测状态区分“未观测到”“已观测到”和“观测不完整”；旧记录缺少状态时为未知。没有事件不等于已经确认连接复用；实际瞬时调用可显示 `0 ms`，无数据仍为空值。取消或后台连接尚未完成时保留部分快照，晚到结果不修改已保存的记录。
- 历史 JSON 中残留的 `dns_ms`、`tcp_ms`、`tls_ms` 不参与新接口输出；无需数据库迁移，旧记录中的其它诊断字段继续按现有兼容规则读取。

## 保存和查询

- 通过现有 `TelemetryWriteQueue` 非阻塞地异步写入 SQLite。正常关闭服务会排空已接收的遥测写入；进程崩溃、队列过载或存储错误时，不保证尚未落库的记录可恢复。
- 持久化记录保留 **7 天或最近 10000 条**，以先到的限制为准。内存保留最近 1000 条；读取会合并并去重，内存较新状态优先。
- 列表最新优先；支持关联 ID、服务器 ID、媒体 ID、结果、用户、关键词、时间范围和最小耗时筛选。先按授权服务器过滤，再筛选和分页；返回数量不会包含无权访问的服务器。
- 列表事务只负责保留策略和授权原始行读取；提交后再做 JSON 解码、脱敏和一致性检查，避免处理整批诊断时持续持有 SQLite 写锁。
- 清空需要超级管理员登录会话、明确确认和审计；同时覆盖此前入队的持久化写入与内存记录，避免旧排队记录在清空后重新出现。清空后产生的新请求仍可继续记录。
- 缺少时间的旧记录不会补造时间戳；没有持久化的历史记录无法通过升级恢复。

## 敏感信息与分享

- 管理员详情仅展示后端已脱敏的数据，并继续执行 `monitoring.read` 与服务器授权；不采集 API Key、Token、Cookie、完整请求头、响应头或原始错误正文。
- 结构化路径和目标 URL 移除凭据、签名查询及片段。不能把诊断中的 URL 当作可直接播放的授权链接。
- 分享复制／JSON 导出只包括明确的安全字段；用户、IP、设备标识及自由文本路径等个人或敏感上下文进一步省略。导出仅覆盖当前已加载页，不会自动抓取全部历史。
- 原始请求关联 ID 用于在既有日志模块中查找同一请求；这些模块的保留期限可能不同，找到诊断不保证相关日志仍在。
- 关联日志页面使用授权服务器选项，不要求全局设置读取权限。日志文件配置只对 `/api/profile` 明确允许的超级管理员会话展示并独立加载，配置失败不会阻止查看已有日志。
